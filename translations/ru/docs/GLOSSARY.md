## Основные понятия

**AI Agent** – Система, использующая ИИ для автономного рассуждения и действий. [Модуль 04](../04-tools/README.md)

**Chain** – Последовательность операций, где выход одного шага становится входом для следующего.

**Chunking** – Разбиение документов на меньшие части. Обычно: 300-500 токенов с перекрытием. [Модуль 03](../03-rag/README.md)

**Context Window** – Максимальное количество токенов, которое модель может обработать. GPT-5.2: 400K токенов (до 272K на вход, 128K на выход).

**Embeddings** – Числовые векторы, представляющие смысл текста. [Модуль 03](../03-rag/README.md)

**Function Calling** – Модель генерирует структурированные запросы для вызова внешних функций. [Модуль 04](../04-tools/README.md)

**Hallucination** – Ситуация, когда модели генерируют некорректную, но правдоподобную информацию.

**Prompt** – Текстовый ввод в языковую модель. [Модуль 02](../02-prompt-engineering/README.md)

**Semantic Search** – Поиск по смыслу с использованием эмбеддингов, а не ключевых слов. [Модуль 03](../03-rag/README.md)

**Stateful vs Stateless** – Stateless: без памяти. Stateful: хранит историю диалога. [Модуль 01](../01-introduction/README.md)

**Tokens** – Базовые единицы текста, которые обрабатывают модели. Влияют на стоимость и ограничения. [Модуль 01](../01-introduction/README.md)

**Tool Chaining** – Последовательное выполнение инструментов, где результат влияет на следующий вызов. [Модуль 04](../04-tools/README.md)

## Компоненты LangChain4j

**AiServices** – Создает типобезопасные интерфейсы AI-сервисов.

**OpenAiOfficialChatModel** – Унифицированный клиент для моделей OpenAI и Azure OpenAI.

**OpenAiOfficialEmbeddingModel** – Создает эмбеддинги с помощью официального клиента OpenAI (поддерживает OpenAI и Azure OpenAI).

**ChatModel** – Основной интерфейс для языковых моделей.

**ChatMemory** – Поддерживает историю диалога.

**ContentRetriever** – Находит релевантные куски документов для RAG.

**DocumentSplitter** – Разбивает документы на части.

**EmbeddingModel** – Преобразует текст в числовые векторы.

**EmbeddingStore** – Хранит и извлекает эмбеддинги.

**MessageWindowChatMemory** – Поддерживает скользящее окно недавних сообщений.

**PromptTemplate** – Создает повторно используемые промпты с плейсхолдерами `{{variable}}`.

**TextSegment** – Текстовый фрагмент с метаданными. Используется в RAG.

**ToolExecutionRequest** – Представляет запрос на выполнение инструмента.

**UserMessage / AiMessage / SystemMessage** – Типы сообщений диалога.

## Концепции ИИ/МО

**Few-Shot Learning** – Предоставление примеров в промптах. [Модуль 02](../02-prompt-engineering/README.md)

**Large Language Model (LLM)** – ИИ-модели, обученные на огромных текстовых данных.

**Reasoning Effort** – Параметр GPT-5.2, контролирующий глубину рассуждения. [Модуль 02](../02-prompt-engineering/README.md)

**Zero-Shot Learning** – Выполнение задач без примеров. [Модуль 02](../02-prompt-engineering/README.md)

## Ограничения безопасности

**Defense in Depth** – Многоуровневый подход к безопасности, сочетающий ограничения на уровне приложения с фильтрами безопасности провайдеров.

**Hard Block** – Провайдер возвращает HTTP 400 ошибку при серьезных нарушениях контента.

**InputGuardrail** – Интерфейс LangChain4j для проверки пользовательского ввода до передачи в LLM. Экономит затраты и задержки, блокируя вредоносные промпты на раннем этапе.

**InputGuardrailResult** – Тип возврата проверки ограничений: `success()` или `fatal("причина")`.

**OutputGuardrail** – Интерфейс проверки ответов ИИ перед возвратом пользователям.

**Provider Safety Filters** – Встроенные фильтры контента от AI-провайдеров (например, Azure OpenAI), блокирующие нарушения на уровне API.

**Soft Refusal** – Модель вежливо отказывается отвечать без генерации ошибки.

## Agentic Модуль - [Модуль 05](../05-mcp/README.md)

**@Agent Annotation** – Маркирует интерфейсы как AI-агентов с декларативным описанием поведения.

**Agent Listener** – Хук для мониторинга выполнения агента через `beforeAgentInvocation()` и `afterAgentInvocation()`.

**Agentic Scope** – Общая память, где агенты сохраняют результаты с помощью `outputKey` для использования другими агентами.

**AgenticServices** – Фабрика для создания агентов с помощью `agentBuilder()` и `supervisorBuilder()`.

**Conditional Workflow** – Маршрутизация к разным специализированным агентам на основе условий.

**Human-in-the-Loop** – Паттерн с добавлением человеческих контрольных точек для одобрения или проверки содержания.

**langchain4j-agentic** – Maven-зависимость для декларативного построения агентов (экспериментальная).

**Loop Workflow** – Итерация выполнения агента до достижения условия (например, качество ≥ 0.8).

**outputKey** – Параметр аннотации агента, указывающий, где сохраняются результаты в Agentic Scope.

**Parallel Workflow** – Параллельный запуск нескольких агентов для независимых задач.

**Response Strategy** – Способ формулирования итогового ответа супервизором: LAST, SUMMARY, или SCORED.

**Sequential Workflow** – Последовательное выполнение агентов, где выход влияет на следующий шаг.

**Supervisor Agent Pattern** – Продвинутый агентный паттерн, в котором супервизор LLM динамически выбирает, каких подагентов вызывать.

## Протокол контекста модели (MCP) - [Модуль 05](../05-mcp/README.md)

**langchain4j-mcp** – Maven-зависимость для интеграции MCP в LangChain4j.

**MCP** – Протокол контекста модели: стандарт для подключения AI-приложений к внешним инструментам. Напиши один раз — используй везде.

**MCP Client** – Приложение, подключающееся к MCP-серверам для обнаружения и использования инструментов.

**MCP Server** – Сервис, предоставляющий инструменты через MCP с описаниями и схемами параметров.

**McpToolProvider** – Компонент LangChain4j, оборачивающий MCP-инструменты для использования в AI-сервисах и агентах.

**McpTransport** – Интерфейс для коммуникации MCP. Реализации: Stdio и HTTP.

**Stdio Transport** – Транспорт локального процесса через stdin/stdout. Полезен для доступа к файловой системе или CLI-инструментам.

**StdioMcpTransport** – Реализация LangChain4j, которая запускает MCP-сервер как подпроцесс.

**Tool Discovery** – Клиент запрашивает у сервера список доступных инструментов с описаниями и схемами.
