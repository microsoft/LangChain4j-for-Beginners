## អ្វីដែលអ្នកនឹងរៀន

មកដល់ពេលនេះ អ្នកបានរៀនពីរបៀបមានការសន្ទនាជាមួយ AI ចាក់សោមកនិយមផ្តើមល្អ និងដាក់មូលដ្ឋានចម្លើយក្នុងឯកសាររបស់អ្នក។ ប៉ុន្តែមានកំណត់មូលដ្ឋានមួយ៖ ម៉ូឌែលភាសាអាចបង្កើតតែក្នុងអត្ថបទប៉ុណ្ណោះ។ ពួកវាមិនអាចពិនិត្យអាកាសធាតុ គណនាលទ្ធផល សាកសួរទិន្នន័យ ឬចូលរួមជាមួយប្រព័ន្ធខាងក្រៅបាន។

ឧបករណ៍ផ្លាស់ប្តូរនេះ។ ដោយផ្តល់ឱ្យម៉ូឌែលនូវមុខងារ ដែលវាអាចហៅបាន អ្នកបម្លែងវា​ពីម៉ាស៊ីនបង្កើតអត្ថបទទៅជា អេយ្យង់ដែលអាចអនុវត្តសកម្មភាពបាន។ ម៉ូឌែលសម្រេចថាតើវាត្រូវការ ឧបករណ៍ណា ដើម្បីប្រើទេ ហើយត្រូវផ្តល់ប៉ារ៉ាម៉ែត្រអ្វី។ កូដរបស់អ្នកអនុវត្តមុខងារនោះហើយ ត្រឡប់លទ្ធផលមកវិញ។ ម៉ូឌែលបញ្ចូលលទ្ធផលនោះទៅក្នុងចម្លើយរបស់វា។

## ការយល់ដឹងអំពីអេយ្យង់ AI ជាមួយឧបករណ៍

> **📝 សម្គាល់៖** ពាក្យថា "អេយ្យង់" ក្នុងម៉ូឌុលនេះ មានន័យជាអ្នកជំនួយ AI ដែលមានសមត្ថភាពហៅឧបករណ៍។ នេះខុសពីគំរូ **Agentic AI** (អេយ្យង់របស់តែម្នាក់ដែលមានការធ្វើដំណើរការប្រកបដោយផែនការ អង្គចងចាំ និងការគិតចម្រុះជាច្រើនជំហាន) ដែលយើងនឹងពិភាក្សា នៅក្នុង [ម៉ូឌុល 05: MCP](../05-mcp/README.md)។

គ្រប់ពេលដែលគ្មានឧបករណ៍ ម៉ូឌែលភាសាអាចបង្កើតបានតែក៍អត្ថបទពីទិន្នន័យហ្វឹកហាត់របស់វា។ សួរអំពីអាកាសធាតុបច្ចុប្បន្ន វាត្រូវតែទាយប៉ុណ្ណោះ។ ផ្តល់ឧបករណ៍វា វាអាចហៅ API អាកាសធាតុ បំពេញកំហិត សាកសួរទិន្នន័យ ហើយបញ្ចូលលទ្ធផលពិតទាំងនោះទៅក្នុងចម្លើយរបស់វា។

<img src="../../../translated_images/km/what-are-tools.724e468fc4de64da.webp" alt="គ្មានឧបករណ៍ ប្រៀបធៀប ជាមួយឧបករណ៍" width="800"/>

*គ្មានឧបករណ៍ ម៉ូឌែលអាចទាយប៉ុណ្ណោះ — មានឧបករណ៍ វាអាចហៅ API ដំណើរការ គណនាលទ្ធផល និងបង្រួមទិន្នន័យពេលវេលាពិត។*

អេយ្យង់ AI ជាមួយឧបករណ៍អនុវត្តគំរូ **Reasoning and Acting (ReAct)**។ ម៉ូឌែលមិនត្រឹមតែឆ្លើយ — វាគិតអំពីអ្វីដែលវាត្រូវការ អនុវត្តដោយហៅឧបករណ៍ មើលលទ្ធផល ហើយសម្រេចចិត្តថាតើត្រូវអនុវត្តបន្ត ឬផ្តល់ចម្លើយចុងក្រោយ៖

១. **គិត** — អេយ្យង់វិភាគសំណួររបស់អ្នកប្រើ ហើយកំណត់ថាត្រូវការព័ត៌មានអ្វី
២. **អនុវត្ត** — អេយ្យង់ជ្រើសរើសឧបករណ៍ត្រឹមត្រូវ បង្កើតប៉ារ៉ាម៉ែត្រត្រឹមត្រូវ ហើយហៅវា
៣. **មើល** — អេយ្យង់ទទួលលទ្ធផលពីឧបករណ៍ និងវាយតំលៃលទ្ធផល
៤. **ធ្វើម្តុំបន្តឬឆ្លើយ** — ប្រសិនបើត្រូវការទិន្នន័យបន្ថែម អេយ្យង់ត្រឡប់ទៅដំណាក់កាលដើម ប្រសិនមិនទេ វាសរសេរចម្លើយភាសាពិតប្រាកដ

<img src="../../../translated_images/km/react-pattern-detail.96a5efeeb6dd2f61.webp" alt="គំរូ ReAct" width="800"/>

*លំនាំ ReAct — អេយ្យង់គិតពីអ្វីដែលត្រូវធ្វើ អនុវត្តដោយហៅឧបករណ៍ មើលលទ្ធផល ហើយធ្វើម្តុំរហូតដល់វាចម្លើយបាន។*

នេះកើតឡើងដោយស្វ័យប្រវត្តិ។ អ្នកកំណត់ឧបករណ៍ និងការពិពណ៌នារបស់ពួកវា។ ម៉ូឌែលទទួលខុសត្រូវលើការសម្រេចចិត្តថាតើពេលណា និងរបៀបប្រើពួកវា។

## វិធីដែលការហៅឧបករណ៍ដំណើរការ

### និយមន័យឧបករណ៍

[WeatherTool.java](../../../04-tools/src/main/java/com/example/langchain4j/agents/tools/WeatherTool.java) | [TemperatureTool.java](../../../04-tools/src/main/java/com/example/langchain4j/agents/tools/TemperatureTool.java)

អ្នកកំណត់មុខងារជាមួយការពិពណ៌នាផ្អែកស្អាត និងការបញ្ជាក់ប៉ារ៉ាម៉ែត្រ។ ម៉ូឌែលមើលការពិពណ៌នាទាំងនេះក្នុង prompt ប្រព័ន្ធរបស់វា ហើយយល់ថាឧបករណ៍នីមួយៗធ្វើអ្វី។

```java
@Component
public class WeatherTool {
    
    @Tool("Get the current weather for a location")
    public String getCurrentWeather(@P("Location name") String location) {
        // ខ lógica ស្វែងរកអាកាសធាតុរបស់អ្នក
        return "Weather in " + location + ": 22°C, cloudy";
    }
}

@AiService
public interface Assistant {
    String chat(@MemoryId String sessionId, @UserMessage String message);
}

// ជំនួយករត្រូវបានភ្ជាប់ដោយ Spring Boot ដោយស្វ័យប្រវត្តិជាមួយ៖
// - កំណត់ Bean ChatModel
// - វិធីសាស្រ្ត @Tool ទាំងអស់ពីថ្នាក់ @Component
```

### ការបង្កើតការឆ្លើយតប

ម៉ូឌែលទទួលបានទិន្នន័យអាកាសធាតុ ហើយបំលែងវាទៅជាចម្លើយភាសាធម្មជាតិសម្រាប់អ្នកប្រើ។

### ស្ថាបត្យកម្ម៖ ការតភ្ជាប់ Spring Boot អូតូ

ម៉ូឌុលនេះប្រើប្រាស់ការតភ្ជាប់ Spring Boot របស់ LangChain4j ជាមួយអ៊ីនធើហ្វេស `@AiService` ដោយប្រកាស។ នៅពេលចាប់ផ្តើម Spring Boot រកឃើញគ្រប់ `@Component` ដែលមានមធ្យោបាយ `@Tool` ទំព័ររបស់អ្នក `ChatModel` ប៊ីន និង `ChatMemoryProvider` — បន្ទាប់មកតភ្ជាប់គ្នាទៅជា អ៊ីនធើហ្វេស Assistant តែមួយដោយគ្មានការចាំបាច់គ្រប់គ្រងនៅដៃ។

<img src="../../../translated_images/km/spring-boot-wiring.151321795988b04e.webp" alt="ស្ថាបត្យកម្មតភ្ជាប់ Spring Boot អូតូ" width="800"/>

*អ៊ីនធើហ្វេស @AiService ភ្ជាប់រួម ChatModel, គ្រឿងផ្នែកឧបករណ៍, និងអ្នកផ្គត់ផ្គង់អង្គចងចាំ — Spring Boot គ្រប់គ្រងការតភ្ជាប់នូវទាំងអស់ដោយស្វ័យប្រវត្តិ។*

នេះជារូបភាពលំដាប់ពេញលេញនៃជីវចក្រសំណើ — ពីសំណើ HTTP តាមរយៈ Controller, Service, និង Proxy តភ្ជាប់ដោយស្វ័យប្រវត្តិ ទៅដល់ការអនុវត្តឧបករណ៍ និងត្រឡប់មកវិញ៖

<img src="../../../translated_images/km/spring-boot-sequence.f83e3d485aa4a3c6.webp" alt="រូបទីតាំងលំដាប់ហៅឧបករណ៍ Spring Boot" width="800"/>

*ជីវចក្រ សំណើ Spring Boot ពេញលេញ — សំណើ HTTP ឌូលបានតាម Controller និង Service ទៅ Proxy Assistant តភ្ជាប់ដោយស្វ័យប្រវត្តិ ដែលបញ្ជាលម្អិត LLM និងការហៅឧបករណ៍ដោយស្វ័យប្រវត្តិ។*

អត្ថប្រយោជន៍សំខាន់ៗនៃវិធីនេះ៖

- **Spring Boot auto-wiring** — ChatModel និងឧបករណ៍ត្រូវបានចាក់បញ្ចូលដោយស្វ័យប្រវត្តិ
- **គំរូ @MemoryId** — ការគ្រប់គ្រងអង្គចងចាំផ្អែកលើសម័យដោយស្វ័យប្រវត្តិ
- **ឧបករណ៍តែមួយ** — Assistant បង្កើតម្តងហើយប្រើបន្តសម្រាប់សមត្ថភាពល្អបំផុត
- **ការអនុវត្តប្រភេទសុវត្ថិភាព** — ហៅវិធីសាស្ត្រ Java ដោយផ្ទាល់ជាមួយការបម្លែងប្រភេទ
- **ការបង្រួមជាច្រើនជំហាន** — គ្រប់គ្រងការច្រកឧបករណ៍ដោយស្វ័យប្រវត្តិ
- **គ្មាន boilerplate** — គ្មានការហៅ `AiServices.builder()` យ៉ាងដៃ អោយ HashMap អង្គចងចាំ។

វិធីនិយមផ្សេងទៀត (ធ្វើដោយដៃ `AiServices.builder()`) ត្រូវការកូដច្រើនជាង និងខ្វះអត្ថប្រយោជន៍របស់ Spring Boot។

ភ្នាក់ងារប្រែប្រួលរវាងការគិត (សម្រេចថាតើត្រូវធ្វើអ្វី) និងការប្រតិបត្តិ (ប្រើឧបករណ៍)។ រចនាប័ទ្មនេះអនុញ្ញាតឲ្យដោះស្រាយបញ្ហាដោយឯករាជ្យ មិនមែនគ្រាន់តែបញ្ចេញចម្លើយតាមបទបញ្ជា។

### ការពិពណ៌នាឧបករណ៍មានសារៈសំខាន់

គុណភាពនៃការពិពណ៌នាឧបករណ៍របស់អ្នកមានឥទ្ធិពលដល់របៀបដែលភ្នាក់ងារប្រើប្រាស់វា។ ការពិពណ៌នាដែលច្បាស់លាស់ និងជាក់លាក់ជួយឲ្យគំរូយល់ថាតើពេលណានិងរបៀបណា ត្រូវហៅឧបករណ៍នីមួយៗ។

### ការគ្រប់គ្រងសម័យសន្ទនា

ការកំណត់ `@MemoryId` អនុញ្ញាតការគ្រប់គ្រងអនុស្សាវរីយ៍តាមសម័យសន្ទនា តាមរយៈ `ChatMemory` ដែលគ្រប់គ្រងដោយ `ChatMemoryProvider` ធ្វើឲ្យអ្នកប្រើច្រើននាក់អាចអន្តរកម្មជាមួយភ្នាក់ងារដូចគ្នាបានដោយមិនចម្រុះជាមួយ។ សំណូមពរបង្ហាញរបៀបដែលអ្នកប្រើប្រាស់ជាច្រើនត្រូវបានបំបែកទៅកាន់ទូរសំឡេងផ្ទាល់ខ្លួនដោយផ្អែកលើសម្គាល់សម័យរបស់ពួកគេ៖

<img src="../../../translated_images/km/session-management.91ad819c6c89c400.webp" alt="ការគ្រប់គ្រងសម័យជាមួយ @MemoryId" width="800"/>

*សម្គាល់សម័យនីមួយៗផ្ទៀងផ្ទាត់ទៅប្រវត្តិជជែកបំបែក - អ្នកប្រើមិនដែលមើលឃើញសាររបស់គ្នាទេ។*

### ការដោះស្រាយកំហុស

ឧបករណ៍អាចបរាជ័យ — អាយភីអាយវេលាមិនគ្រប់គ្រាន់ ប៉ារ៉ាម៉ែត្រអាចមិនត្រឹមត្រូវ សេវាកម្មខាងក្រៅអាចទៀតពេល។ ភ្នាក់ងារផលិតកម្មត្រូវការការដោះស្រាយកំហុស ដើម្បីឲ្យគំរូអាចពន្យល់បញ្ហា ឬសាកល្បងជម្រើសផ្សេងៗដោយមិនបង្កើតកំហុសធំទូលាយវិញ។ ឧបករណ៍បោះសំណើកំហុស LangChain4j ចាប់យក ហើយផ្ញើសារបញ្ហាចូលទៅគំរូ ដែលបន្ទាប់មកអាចពន្យល់បញ្ហានោះជាភាសាធម្មជាតិ។

## ឧបករណ៍ដែលមាន

គំនូរសូមមើលខាងក្រោមបង្ហាញពីប្រព័ន្ធឧបករណ៍ដែលអ្នកអាចកសាង។ ម៉ូឌុលនេះបង្ហាញឧបករណ៍អាកាសធាតុ និងសីតុណ្ហភាព ប៉ុន្តែរចនាប័ទ្ម `@Tool` ដូចគ្នាអាចប្រើសម្រាប់មធ្យោបាយ Java ទាំងអស់ — ពីការស្វែងយល់ទិន្នន័យទៅដល់ការចំណាយប្រាក់។

<img src="../../../translated_images/km/tool-ecosystem.aad3d74eaa14a44f.webp" alt="ប្រព័ន្ធឧបករណ៍" width="800"/>

*មធ្យោបាយ Java ណាមួយដែលមាន `@Tool` នឹងអាចប្រើបានដោយ AI — រចនាប័ទ្មពង្រីកទៅកាន់ទិន្នន័យ, API, អ៊ីមែល, ប្រតិបត្តិការឯកសារ និងវែងទៀត។*

## ពេលណា គួរប្រើភ្នាក់ងារតាមឧបករណ៍

មិនមែនសំណើរ​ទាំងអស់ត្រូវការឧបករណ៍ទេ។ ការសម្រេចចិត្តនៅផ្តល់តម្លៃថា AI ត្រូវអន្តរកម្មជាមួយប្រព័ន្ធខាងក្រៅរឺអាចឆ្លើយពីចំណេះដឹងផ្ទាល់ខ្លួន។ មគ្គុទេសក៍ខាងក្រោមសង្ខេបពេលណាឧបករណ៍មានតម្លៃ និងពេលណាអត់ត្រូវការ៖

<img src="../../../translated_images/km/when-to-use-tools.51d1592d9cbdae9c.webp" alt="ពេលណា គួរប្រើឧបករណ៍" width="800"/>

*មគ្គុទេសក៍សម្រេចឆាប់ - ឧបករណ៍សម្រាប់ទិន្នន័យបច្ចុប្បន្ន, ការគណនា និងសកម្មភាព; ចំណេះដឹងទូទៅ និងភារកិច្ចបង្កើតមិនត្រូវការវា។*

## ឧបករណ៍ប្រៀបធៀប RAG

ម៉ូឌុល ០៣ និង ០៤ ពង្រីកអ្វីដែល AI អាចធ្វើបាន ប៉ុន្តែមានរបៀបខុសគ្នាចម្បង។ RAG ផ្ដល់ការចូលដំណើរការចំណេះដឹងដោយស្វែងយល់ឯកសារ។ ឧបករណ៍ផ្ដល់សមត្ថភាពធ្វើសកម្មភាពដោយហៅមុខងារ។ រូបភាពខាងក្រោមប្រៀបធៀបពីររបៀបនេះជាបន្ទាត់ជាមួយ — ពីរបៀបដំណើរការដល់ការជ្រាបចំណាយរវាងពួកវា៖

<img src="../../../translated_images/km/tools-vs-rag.ad55ce10d7e4da87.webp" alt="ប្រៀបធៀបឧបករណ៍និង RAG" width="800"/>

*RAG ស្វែងយល់ពីឯកសារស្ថិតស្ថេរ — ឧបករណ៍អនុវត្តសកម្មភាព និងយកទិន្នន័យបច្ចុប្បន្នសកម្មភាព ដំណើរការកម្មវិធីច្រើនប្រព័ន្ធផ្សំគ្នាទាំងពីរ។*

នៅក្នុងអនុវត្តន៍ កម្មវិធីផលិតភាពច្រើនប្រើរួមគ្នា៖ RAG សម្រាប់ផ្តល់មូលដ្ឋានចម្លើយក្នុងឯកសារ និងឧបករណ៍សម្រាប់យកទិន្នន័យបច្ចុប្បន្ន ឬអនុវត្តសកម្មភាព។
