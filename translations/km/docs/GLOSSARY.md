## មូលដ្ឋានគំនិត

**ភ្នាក់ងារ AI** - ប្រព័ន្ធដែលប្រើ AI ដើម្បីចង្អុលសេចក្ដីហើយអនុវត្តដោយស្វ័យប្រវត្តិ។ [Module 04](../04-tools/README.md)

**ខ្សែ** - ជួរនៃប្រតិបត្តិការដែលលទ្ធផលចេញដល់ជំហានបន្ទាប់។

**ការបែងចែកឯកសារ** - ការបំបែកឯកសារជាចំណែកតូចៗ។ ឧទាហរណ៍: 300-500 តូចខ្ទង់ដោយប្រែប្រួលស្ទើរតែមានអនុលូមក។ [Module 03](../03-rag/README.md)

**បង្អួចបរិបទ** - បរិមាណតូចបំផុតនៃតូចខ្ទង់ដែលម៉ូឌែលអាចដំណើរការ។ GPT-5.2: 400K តូចខ្ទង់ (រហូតដល់ 272K បញ្ចូល, 128K លទ្ធផលចេញ)។

**ការបញ្ចូលអក្សរ​** - វិចិត្រស័ក្តិលេខគណនាដែលជាតំណាងអត្ថន័យអក្សរ។ [Module 03](../03-rag/README.md)

**ការហៅមុខងារ** - ម៉ូឌែលបង្កើតសំណើរ​រចនាសម្ព័ន្ធសម្រាប់ហៅមុខងារនៅក្រៅ។ [Module 04](../04-tools/README.md)

**ការស្រមៃពិតប្រាកដ** - ពេលដែលម៉ូឌែលបង្កើតព័ត៌មានមិនត្រឹមត្រូវប៉ុន្តែមើលទៅឆ្ងល់។

**prompt** - អក្សរបញ្ចូលទៅម៉ូឌែលភាសា។ [Module 02](../02-prompt-engineering/README.md)

**ស្វែងរកដោយមនុស្សអត្ថន័យ** - ស្វែងរកដោយផ្អែកលើអត្ថន័យប្រើ embeddings មិនមែនពាក្យគន្លឹះ។ [Module 03](../03-rag/README.md)

**Stateful vs Stateless** - Stateless: គ្មានចងចាំ។ Stateful: រក្សាបរិបទនៃការសន្ទនា។ [Module 01](../01-introduction/README.md)

**តូចខ្ទង់** - ឯកតាអក្សរមូលដ្ឋានដែលម៉ូឌែលដំណើរការ។ ប៉ះពាល់តម្លៃនិងដែនកំណត់។ [Module 01](../01-introduction/README.md)

**Tool Chaining** - ការប្រើឧបករណ៍ជាដំណាក់កាលដែលលទ្ធផលចេញជួយក្នុងការហៅបន្ទាប់។ [Module 04](../04-tools/README.md)

## ធាតុ LangChain4j

**AiServices** - បង្កើតចំណុចបំផុតសេវាកម្ម AI មានប្រភេទត្រឹមត្រូវ។

**OpenAiOfficialChatModel** - អតិថិជនតែមួយសម្រាប់ម៉ូឌែល OpenAI និង Azure OpenAI ។

**OpenAiOfficialEmbeddingModel** - បង្កើត embeddings ដោយប្រើអតិថិជន OpenAI ក្នុងផ្លូវការរួមទាំង OpenAI និង Azure OpenAI។

**ChatModel** - ចំណុចបំផុតសម្រាប់ម៉ូឌែលភាសា។

**ChatMemory** - រក្សាបរិបទនៃការសន្ទនា។

**ContentRetriever** - ស្វែងរកចំណែកឯកសារដែលសមស្របសម្រាប់ RAG។

**DocumentSplitter** - បំបែកឯកសារជាចំណែកតូចៗ។

**EmbeddingModel** - បំលែងអត្ថបទទៅជាវិចិត្រស័ក្តិលេខ។

**EmbeddingStore** - ទីតាំងស្តុកនិងយក embeddings។

**MessageWindowChatMemory** - រក្សាបង្អួចបង្ហាញសារថ្មីៗនៃសារ។

**PromptTemplate** - បង្កើត prompt ដែលអាចប្រើឡើងវិញជាមួយ `{{variable}}` ។

**TextSegment** - ចំណាត់ក្រុមអក្សរជាមួយព័ត៌មានបន្ថែម។ ប្រើក្នុង RAG។

**ToolExecutionRequest** - បង្ហាញសំណើរប្រើឧបករណ៍។

**UserMessage / AiMessage / SystemMessage** - ប្រភេទសារសន្ទនា។

## គំនិត AI/ML

**ការរៀនពីគំរូតិច** - ផ្ដល់ឧទាហរណ៍ក្នុង prompt ។

**ម៉ូឌែលភាសាជាតួធំ (LLM)** - ម៉ូឌែល AI ដែលបានហ្វឹកហាត់លើទិន្នន័យអត្ថបទធំ។

**កំរិតការសំរាប់ហេតុផល** - ប៉ារ៉ាម៉ែត្រ GPT-5.2 ដែលគ្រប់គ្រងជម្រៅនៃការគិតសំរាប់ហេតុផល។

**សីតុណ្ហភាព** - គ្រប់គ្រងភាពចៃដន្យនៃលទ្ធផល។ ទាប=ច្បាស់លាស់, ខ្ពស់=បង្កើតភាពច្នៃប្រឌិត។

**មូលដ្ឋានទិន្នន័យវិចិត្រស័ក្តិ** - មូលដ្ឋានទិន្នន័យពិសេសសម្រាប់ embeddings។ [Module 03](../03-rag/README.md)

**ការរៀនពីគំរូសូន្យ** - ការប្រតិបត្តិការដោយគ្មានឧទាហរណ៍។ [Module 02](../02-prompt-engineering/README.md)

## ឧបករណ៍ការពារ

**ការពារជាន់ខ្ពស់** - វិធីសាស្រ្តសុវត្ថិភាពច្រើនស្រទាប់រួមបញ្ចូល guardrails កម្រិតកម្មវិធីជាមួយនឹងតម្រងសុវត្ថិភាពរបស់អ្នកផ្គត់ផ្គង់។

**ការរាំងខ្ទប់តឹងរឹង** - អ្នកផ្គត់ផ្គង់បោះបង់កំហុស HTTP 400 សម្រាប់ការបំពានខ្លាំង។

**InputGuardrail** - ចំណុចប្រទាក់ LangChain4j សម្រាប់ផ្ទៀងផ្ទាត់បញ្ចូលអ្នកប្រើ មុនវាចូល LLM។ ជួយសន្សំថ្លៃនិងពេលវេលា ដោយរាំងខ្ទប់ prompt ដែលមានគ្រោះថ្នាក់បានមុនពេលពេញលេញ។

**InputGuardrailResult** - ប្រភេទត្រឡប់សម្រាប់ការផ្ទៀងផ្ទាត់ guardrail៖ `success()` ឬ `fatal("reason")`។

**OutputGuardrail** - ចំណុចប្រទាក់សម្រាប់ផ្ទៀងផ្ទាត់ចម្លើយ AI មុនទទួលទៅអ្នកប្រើ។

**តម្រងសុវត្ថិភាពអ្នកផ្គត់ផ្គង់** - តម្រងមាតិកាដែលបានបង្កើតជំនួយពីអ្នកផ្គត់ផ្គង់ AI (ឧ. Azure OpenAI) ដែលចាប់ឃើញការបំពាននៅកម្រិត API។

**ការបដិសេធស្រាល** - ម៉ូឌែលអធ្យាស្រ័យបដិសេធឆ្លើយតបដោយគ្មានកំហុស។

## Prompt Engineering - [Module 02](../02-prompt-engineering/README.md)

**Chain-of-Thought** - ដំណើរគំនិតជាដំណាក់កាល សម្រាប់ភាពត្រឹមត្រូវកាន់តែល្អ។

**លទ្ធផលកំណត់** - បង្ខំទ្រង់ទ្រាយ ឬរចនាសម្ព័ន្ធជាក់លាក់។

**ភាពឆាប់រហ័សខ្ពស់** - រចនាសម្ព័ន្ធ GPT-5.2 សម្រាប់ការគិតហេតុផលយ៉ាងពេញលេញ។

**ភាពឆាប់រហ័សទាប** - រចនាសម្ព័ន្ធ GPT-5.2 សម្រាប់ចម្លើយរហ័ស។

**ការសន្ទនាច្រើនជុំ** - រក្សាឯកសារបរិបទជាមធ្យមក្នុងការផ្លាស់ប្ដូរព័ត៌មាន។

**ការផ្ដល់ Prompt ផ្អែកលើតួនាទី** - កំណត់ពិណាណម៉ូឌែលតាមសាររបស់ប្រព័ន្ធ។

**ការពិចារណាខ្លួនឯង** - ម៉ូឌែលវាយតម្លៃ និងបង្កើតលទ្ធផលល្អប្រសើរឡើង។

**វិភាគមានរចនាសម្ព័ន្ធ** - ឯកសារវាយតម្លៃច្បាស់លាស់។

**លំនាំអនុវត្តភារកិច្ច** - ប្លង់ → អនុវត្ត → សង្ខេប។

## RAG (ការបង្កើតបន្ថែមដោយការស្ទង់តាម) - [Module 03](../03-rag/README.md)

**ស្រង់បច្ចេកទេសឯកសារ** - បង្ហាញ → បំបែក → បញ្ចូល → ស្តុក។

**ការផ្ទុក Embedding នៅក្នុងអង្គចងចាំ** - ទីតាំងមិនថ្លៃចិត្តសម្រាប់ការតេស្ត។

**RAG** - ផ្តល់កំរិតការស្វែងរក រួមជាមួយបង្កើតដើម្បីបម្រុងការឆ្លើយតប។

**ពិន្ទុស្រដៀង** - វាស់ (0-1) នៃស្រដៀងដោយអត្ថន័យ។

**យោងប្រភព** - ព័ត៌មានបន្ថែមអំពីមាតិកាដែលបានរកឃើញ។

## ភ្នាក់ងារ និង ឧបករណ៍ - [Module 04](../04-tools/README.md)

**@Tool Annotation** - កំណត់វិធីសាស្រ្ត Java ជាឧបករណ៍ដែលអាចហៅបានដោយ AI។

**លំនាំ ReAct** - គិត → អនុវត្ត → ទស្សនា → តម្រូវឡើងវិញ។

**ការគ្រប់គ្រងវគ្គសិក្សា** - បរិបទបំបែកសម្រាប់អ្នកប្រើប្រាស់ផ្សេងៗ។

**ឧបករណ៍** - មុខងារដែលភ្នាក់ងារ AI អាចហៅបាន។

**ការពណ៌នាឧបករណ៍** - ឯកសារអំពីគោលបំណងនិងប៉ារ៉ាម៉ែត្រ។

## ម៉ូឌុល Agentic - [Module 05](../05-mcp/README.md)

**@Agent Annotation** - កំណត់ចំណុចប្រទាក់ជាភ្នាក់ងារ AI ជាមួយនឹងការបរិយាយអាកប្បកិរិយា។

**Agent Listener** - Hook សម្រាប់តាមដានការអនុវត្តភ្នាក់ងារ តាមរយៈ `beforeAgentInvocation()` និង `afterAgentInvocation()`។

**Agentic Scope** - អង្គចងចាំរួមដែលភ្នាក់ងារផ្ទុកលទ្ធផលប្រើ `outputKey` សម្រាប់ភ្នាក់ងារផ្សេងទៀតប្រើបន្ត។

**AgenticServices** - រោងចក្រ បង្កើតភ្នាក់ងារដោយប្រើ `agentBuilder()` និង `supervisorBuilder()`។

**ដំណើរការដោយមានលក្ខ័ខណ្ឌ** - ផ្លូវទៅតាមលក្ខខណ្ឌទៅភ្នាក់ងារជំនាញផ្សេងៗ។

**មនុស្សនៅក្នុងសៀវភៅ** - លំនាំដំណើរការខ្សែភ្នាក់ងារដែលបន្ថែមចំណុចមនុស្សសម្រាប់អនុម័ត ឬពិនិត្យមាតិកា។

**langchain4j-agentic** - Maven dependency សម្រាប់ការបង្កើតភ្នាក់ងារជាសេចក្តីប្រកាស (ការប្រឡង)។

**លំនាំ Loop** - វដ្តការអនុវត្តភ្នាក់ងារដល់ពេលលទ្ធផលបំពេញលក្ខណៈ (ឧ. ពិន្ទុគុណភាព ≥ 0.8) ។

**outputKey** - ប៉ារ៉ាម៉ែត្រ annotation ភ្នាក់ងារ បញ្ជាក់កន្លែងដែលលទ្ធផលត្រូវផ្ទុកក្នុង Agentic Scope។

**លំនាំប្រតិបត្តិការជាប្រព័ន្ធ 병ឹះ** - រត់ភ្នាក់ងារច្រើនជាសមាជិកសម្រាប់ភារកិច្ចឯករាជ្យ។

**យុទ្ធសាស្រ្តចម្លើយ** - របៀបដែលអ្នកគ្រប់គ្រងបង្ហាញចម្លើយចុងក្រោយ៖ LAST, SUMMARY, ឬ SCORED។

**លំនាំប្រតិបត្តិការតម្រង់តំណរដោយលំដាប់** - អនុវត្តភ្នាក់ងារតាមលំដាប់ដែលលទ្ធផលចេញទៅជាជំហានបន្ទាប់។

**លំនាំ Supervisor Agent** - លំនាំ agentic ដែលស្ថិតនៅកម្រិតខ្ពស់ ស្ថិតនៅលើ LLM អ្នកគ្រប់គ្រង ដែលសម្រេចចិត្តផ្ទាល់ពីភ្នាក់ងារតូចៗដើម្បីហៅ។

## ពិធីការបរិបទម៉ូឌែល (MCP) - [Module 05](../05-mcp/README.md)

**langchain4j-mcp** - Maven dependency សម្រាប់ការរួមបញ្ចូល MCP ក្នុង LangChain4j ។

**MCP** - ពិធីការបរិបទម៉ូឌែល៖ ស្តង់ដារសម្រាប់ភ្ជាប់កម្មវិធី AI ទៅឧបករណ៍ក្រៅ។ សាងសង់ម្តង ប្រើបានគ្រប់ទីកន្លែង។

**អតិថិជន MCP** - កម្មវិធីភ្ជាប់ទៅម៉ាស៊ីនបម្រើ MCP ដើម្បីរកឧបករណ៍ និងប្រើវា។

**ម៉ាស៊ីនបម្រើ MCP** - សេវាកម្មបង្ហាញឧបករណ៍តាមរយៈ MCP ជាមួយនឹងការពិពណ៌នាច្បាស់លាស់និង schemas ប៉ារ៉ាម៉ែត្រ។

**McpToolProvider** - ធាតុ LangChain4j ដែលរុំឧបករណ៍ MCP សម្រាប់ប្រើប្រាស់ក្នុងសេវាកម្ម AI និងភ្នាក់ងារ។

**McpTransport** - ចំណុចប្រទាក់សម្រាប់ការទំនាក់ទំនង MCP។ ការអនុវត្តមាន Stdio និង HTTP។

**Stdio Transport** - ការដឹកជញ្ជូនដំណើរការតំបន់បណ្ដាញតាមរយៈ stdin/stdout។ ប្រយោជន៍សម្រាប់ចូលប្រព័ន្ធឯកសារ ឬឧបករណ៍បញ្ជា។

**StdioMcpTransport** - អនុវត្ត LangChain4j ដែលបង្កើតម៉ាស៊ីនបម្រើ MCP ជាដំណើរការ​ជាប់ផ្នែកក្រោម។

**ការស្វែងរកឧបករណ៍** - អតិថិជនសួរម៉ាស៊ីនបម្រើ ដើម្បីស្វែងរកឧបករណ៍ដែលមានជាមួយពិពណ៌នានិង schemas។
